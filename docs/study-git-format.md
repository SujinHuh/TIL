# 학습 기록 Git 게시 형식

이 문서는 TLI 학습 기록을 검수하고 사용자의 승인을 받은 뒤 GitHub `main`에 직접 게시하는 절차를 정의한다.

## 기본 원칙

- TLI 학습 기록 게시에서는 PR을 생성하지 않는다.
- 검수된 최신 최종본과 사용자가 승인한 파일만 `main`에 직접 반영한다.
- 관련 없는 변경이나 승인되지 않은 파일은 stage, commit 또는 push하지 않는다.
- force push는 사용하지 않는다.

## 게시 승인 경계

1. Daily와 Concepts 초안은 채팅으로만 제시한다.
2. 사용자가 회고 원문, Concepts 선택, 공부 시간, 제목과 게시 경로를 확인한다.
3. 작성자와 분리된 실제 서브 에이전트가 최신 초안을 읽기 전용으로 검수한다.
4. 작성자가 검수 결과를 반영한 최종본과 게시 대상 파일을 채팅으로 다시 제시한다.
5. 사용자가 아래 승인 문구 중 하나를 검수된 최신 최종본을 가리키는 실제 명령으로 사용한 경우에만 파일 작성, commit과 `origin/main` push를 진행한다.

최종 게시 승인 문구는 다음과 같다.

- `이대로 Git에 올려줘`
- `최종 Git에 올려줘`
- `완료 Git`
- `Git에 올려줘`
- `Git에 push 해줘`

질문, 인용, 예시, 규칙 논의 과정에서 승인 문구가 나온 것은 게시 승인으로 처리하지 않는다.

## 커밋 형식

Daily만 추가하는 기본 커밋 메시지는 다음과 같다.

```text
docs: add YYYY-MM-DD study reflection
```

Daily와 Concepts 또는 지침 문서를 함께 게시하면 실제 변경 범위를 포괄하는 짧은 커밋 메시지를 사용한다. 커밋에는 사용자가 승인한 파일만 포함한다.

## `main` 직접 게시 절차

1. 원격 `main`의 최신 상태와 현재 worktree 변경을 확인한다.
2. 기존 작업과 섞일 가능성이 있으면 원격 `main`을 깨끗한 임시 디렉터리에 복제해 작업한다.
3. 사용자가 승인한 최신 최종본만 파일에 반영한다.
4. `git status`와 diff를 확인하고 승인된 정확한 경로만 `git add`한다.
5. staged diff와 `git diff --cached --check`를 확인한다.
6. 현재 브랜치가 `main`인지 확인하고 승인된 파일만 commit한다.
7. `git push origin main`으로 원격 `main`에 직접 push한다.
8. `git ls-remote origin refs/heads/main`으로 원격 SHA를 조회해 로컬 HEAD와 일치하는지 확인한다.
9. 사용자에게 커밋 SHA, 변경 범위와 원격 반영 결과를 보고한다.

## push 충돌과 실패 처리

- 일반 push가 거절되면 force push하지 않는다.
- 원격 `main`의 최신 상태를 다시 확인하고, 최신 상태 위에 승인된 변경만 재적용한다.
- 재적용 후 `git status`, staged diff와 `git diff --cached --check`를 다시 확인한다.
- 네트워크 오류 등으로 원격 SHA를 확인하지 못했다면 게시가 확인됐다고 단정하지 않는다.
